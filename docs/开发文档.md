## 1. 目录结构与职责边界

项目基于 Next.js 16 App Router，路径别名 `@/*` 指向 `src/*`（见 `tsconfig.json`）。

```text
src/
├── api/                     # HTTP 实例与按领域拆分的接口函数
│   ├── http.ts              # Axios 实例、Token 注入、统一响应解包与异常处理
│   └── <module>.ts          # 各模块 API（如 banner.ts、department.ts）
├── app/                     # Next.js App Router 路由与页面
│   ├── layout.tsx           # 根布局、字体、ThemeProvider、SEO Metadata/JSON-LD
│   ├── page.tsx             # 系统首页
│   ├── login/               # 登录页（无侧边栏布局）
│   ├── api/[...slug]/       # 开发环境本地 Mock 单入口路由转发
│   └── <domain>/<module>/   # 业务模块页面目录（见第 5 节）
├── components/
│   ├── ui/                  # Shadcn/ui + Radix 基础组件（源码可控）
│   ├── custom/              # 业务级封装组件（CustomTable / CustomForm / CustomDialog / FileUpload 等）
│   └── layout/              # 布局壳（ConditionalLayout / Layout / AppSidebar / NavMain）
├── config/                  # 全局常量与映射配置
│   ├── api-url.ts           # API_BASE_URL、UPLOAD_API_URL、API_URLS 集中定义
│   ├── routes.ts            # MenuResource -> RouteConfig 转换器、iconMap、colorMap
│   ├── constants.ts         # API_CODE 状态码常量
│   ├── forbidden-flag.ts    # 启禁用状态枚举（0=启用, 1=禁用）与 UI 样式配置
│   ├── pagination.ts        # DEFAULT_PAGE_SIZE 等分页默认配置
│   ├── site.ts              # 站点 URL 与 SEO 元数据配置
│   └── theme-colors.ts      # 预置主题色变量定义
├── hooks/                   # 通用 React Hooks（useDebounce / useToast / useMobile 等）
├── lib/                     # 纯工具模块（auth.ts / menu-cache.ts / utils.ts）
├── mock/                    # 本地 Mock 引擎与分模块数据（生产环境自动返回 404）
│   ├── index.ts             # 路由表汇总与 dispatchMockRequest 分发器
│   ├── utils.ts             # mockSuccess / mockError / paginate / checkMockAuth
│   └── modules/<domain>/    # 各领域 Mock 路由与 globalThis 内存仓库
├── store/                   # Zustand 状态管理
│   ├── index.ts             # 持久化主 Store（app-slice + sidebar-slice）
│   └── slices/menu-slice.ts # 独立菜单 Store（useMenuStore）
├── styles/globals.css       # Tailwind CSS 4 入口、深浅模式 CSS 变量、滚动条样式
└── types/                   # TypeScript 类型定义（api.ts 及各领域模型）
```

## 2. 运行时架构与核心数据流

### 2.1 布局与路由壳

```text
RootLayout (src/app/layout.tsx)
 └─ ThemeProvider (next-themes, class="dark")
     ├─ ConditionalLayout (src/components/layout/conditional-layout.tsx)
     │   ├─ 命中 NO_LAYOUT_PATHS（默认 ["/login"]） -> 直接渲染 children
     │   └─ 其余路由 -> Layout (src/components/layout/layout.tsx)
     │       ├─ AppSidebar (消费 useMenuStore.menuItems)
     │       ├─ Header (面包屑自动按 pathname 匹配 menuItems)
     │       └─ 主内容卡片容器 (bg-background dark:bg-white/[0.03])
     └─ Toaster
```

### 2.2 认证与动态菜单流

1. **登录**：`src/app/login/page.tsx` 对密码做 MD5 后调用 `POST /auth/login`，将 `accessToken` 存入 `localStorage['access-token']`，解析 JWT `content` 存入 `localStorage['user-info']`。
2. **鉴权注入**：`src/api/http.ts` 请求拦截器从 `getToken()` 读取 `access-token`，自动写入请求头 `Access-Token`。
3. **菜单加载**：侧边栏触发 `useMenuStore.getState().fetchMenus()`：
   - 优先读取 `menuCache.get()`（`src/lib/menu-cache.ts`，30 分钟 TTL）。
   - 缓存未命中时请求 `GET API_URLS.auth.resources`（`/auth/resource/employeeAuthResources`）。
   - 调用 `convertMenuToRoutes()`（`src/config/routes.ts`）按 `sort` 排序，并根据 `resourceId` 从 `iconMap` / `colorMap` 匹配图标与颜色，拼接到静态首页路由之后。
4. **登出 / 登录失效**：响应码为 `API_CODE.UNLOGIN`（`'UN_LOGIN'`）时，响应拦截器调用 `clearAuth()`（清理 `localStorage` 并执行 `resetMenuStore()` 清空菜单缓存）并跳转 `/login`。

### 2.3 网络请求与响应解包规则

`src/api/http.ts` 的响应拦截器**直接解包返回 `ApiResponse` 对象**（而不是 Axios 的 `AxiosResponse`）：

```ts
// src/types/api.ts
export interface ApiResponse<T = any> {
  code: string   // 'OK' | 'UN_LOGIN' | 'UN_AUTH' | 'ERROR' | 'EMPTY' | 'PARAM_ERROR'
  data: T
  msg: string
  count?: number // 分页列表总数
}
```

- 当 `res.code === 'OK'` 时，拦截器返回 `res` 本身，调用方直接读 `res.data` 与 `res.count`。
- 当 `res.code !== 'OK'` 或网络超时/异常时，拦截器**已自动弹出 `showError()` 通知**并 `Promise.reject(new Error(...))`。业务层 `catch` 中若无需重复提示，可直接做状态收尾；若需自定义标题提示（如“新增失败”），再调用 `showError`。
- 文件上传独立使用 `UPLOAD_API_URL`（见 `src/api/upload.ts`）。

### 2.4 状态管理约定

| Store / Hook | 来源 | 持久化 | 用途 |
|---|---|---|---|
| `useStore` | `src/store/index.ts` | `localStorage['app-storage']` | 侧边栏开关、页面标题、搜索区折叠状态 |
| `usePageTitle()` | `src/store/index.ts` | 随主 Store | 页面挂载时设置当前页标题 |
| `useSearchArea()` / `useSearchCollapse()` | `src/store/index.ts` | 随主 Store | 控制顶部搜索栏折叠按钮的显隐与展开态 |
| `useMenuStore` | `src/store/slices/menu-slice.ts` | 独立 `menuCache`（30min） | 动态菜单树、展开集合、加载状态 |

## 3. 环境变量与本地 Mock 机制

### 3.1 环境文件切换

| 文件 | 对应脚本 | `NEXT_PUBLIC_API_URL` | 说明 |
|---|---|---|---|
| `.env.development` | `yarn dev` / `yarn build:dev` | `/api` | 走 Next.js 本地 Mock |
| `.env.test` | `yarn dev:test` / `yarn build:test` | `http://localhost:5001/api` | 对接本地/测试后端 |
| `.env.production` | `yarn build:prod` / `yarn start:prod` | 真实后端地址 | 生产环境（同时配置 `NEXT_PUBLIC_SITE_URL`） |

### 3.2 本地 Mock 链路

```text
浏览器请求 /api/bms/operation/banner/queryPage
  -> src/app/api/[...slug]/route.ts (支持 GET/POST/PUT/DELETE/PATCH)
  -> src/mock/index.ts :: dispatchMockRequest(request, method, path)
     ├─ 若 NEXT_PUBLIC_ENV === 'production' -> 直接返回 404
     └─ 按 `${METHOD} ${API_URLS.xxx}` 命中处理函数 -> 读写 globalThis 内存仓库
```

- 路由键**必须直接引用 `API_URLS` 常量**（如 `` [`GET ${API_URLS.banner.list}`] ``），避免路径拼写漂移。
- 内存数据挂载在 `globalThis` 上，保证开发环境 HMR 热更新时增删改数据不丢失。
- 开发态可见菜单由 `src/mock/modules/auth/data.ts` 中的 Mock 菜单树控制。

## 4. 新增一个业务模块（标准 6 步 SOP）

以在 `<domain>` 域下新增 `<module>` 模块（如 `operation/notice`）为例，完整流程如下：

### Step 1：定义类型模型

新建 `src/types/<module>.ts`：

```ts
export interface Notice {
  noticeId: string
  noticeTitle: string
  sort: number
  forbiddenFlag: number // 0 = 启用, 1 = 禁用（遵循 FORBIDDEN_FLAG_CONFIG）
  insertTime?: string
}
```

### Step 2：注册接口路径与 API 封装

1. 在 `src/config/api-url.ts` 的 `API_URLS` 中追加模块路径：

```ts
notice: {
  list: '/bms/operation/notice/queryPage',
  save: '/bms/operation/notice/addOrEdit',
  disable: '/bms/operation/notice/disable',
  delete: '/bms/operation/notice/delete',
},
```

2. 新建 `src/api/<module>.ts`：

```ts
import { http } from './http'
import { API_URLS } from '@/config/api-url'
import type { ApiResponse } from '@/types/api'
import type { Notice } from '@/types/notice'

export interface NoticeQuery {
  page: number
  limit: number
  noticeTitle?: string
  forbiddenFlag?: number
}

export const getNoticeList = (params: NoticeQuery) =>
  http.get(API_URLS.notice.list, { params }) as unknown as Promise<ApiResponse<Notice[]>>

export const saveNotice = (params: Partial<Notice>) =>
  http.post(API_URLS.notice.save, params)

export const toggleNoticeForbiddenFlag = (params: { ids: string; value: number }) =>
  http.post(API_URLS.notice.disable, params)

export const deleteNotice = (ids: string) =>
  http.post(API_URLS.notice.delete, { ids })
```

### Step 3：创建页面路由与 CRUD 组件

在 `src/app/<domain>/<module>/` 下按统一三文件结构组织（参考 `src/app/operation/banner/` 或 `src/app/base/tag/`）：

```text
src/app/<domain>/<module>/
├── page.tsx            # 路由入口：export default NoticePage
├── <module>-index.tsx  # 列表页：搜索栏 + 批量操作 + CustomTable + ConfirmDialog + Edit 弹窗
└── <module>-edit.tsx   # 新增/编辑弹窗：CustomDialog + CustomForm + Zod Schema
```

关键编码规范：
- 列表页顶层容器使用 `flex h-full flex-col overflow-hidden`，表格外层包裹 `flex-1 min-h-0` 以保证表头吸顶与表体内部滚动正常。
- 挂载时调用 `setPageTitle('<模块名>')`。
- 关键词搜索使用 `useDebounce(searchKeyword, 800)` 防抖；状态筛选直接复用 `FORBIDDEN_FLAG_OPTIONS` / `FORBIDDEN_FLAG_CONFIG`。
- `columns` 建议用 `useMemo` 包裹，避免父组件状态变化时引起 `CustomTable` 行级重渲染。
- 表格复选框列使用 `key: 'selection'`、`align: 'center'`、`width: 40`，`CustomTable` 已对其做无水平内边距居中处理。

### Step 4：注册菜单图标与颜色

在 `src/config/routes.ts` 中为后端约定的 `resourceId` 补充映射（未配置时自动降级到 `default`）：

```ts
// iconMap
noticeManage: Bell,

// colorMap
noticeManage: "text-blue-500",
```

### Step 5：配置后端菜单或补齐本地 Mock

- **真实后端模式**：在后端权限/菜单资源表中注册 `path: '/<domain>/<module>'` 与 `resourceId: 'noticeManage'`，重新登录或清理 `menuCache` 后侧边栏自动出现。
- **本地 Mock 模式**：
  1. 在 `src/mock/modules/<domain>/data.ts` 添加初始数据与自增 ID。
  2. 新建 `src/mock/modules/<domain>/<module>.ts` 实现 CRUD 路由（参考 `src/mock/modules/operation/banner.ts`）。
  3. 在 `src/mock/index.ts` 将新路由展开合入 `mockRoutes`。
  4. 在 `src/mock/modules/auth/data.ts` 的菜单树中添加对应节点（`path: '/<domain>/<module>'`）。

### Step 6：类型生成与静态检查

```bash
npx next typegen && npx tsc --noEmit
```

## 5. 修改已有模块速查

| 变更场景 | 涉及文件 | 注意事项 |
|---|---|---|
| **列表新增/调整列** | `src/types/<m>.ts` → `*-index.tsx` 的 `columns` | 固定列需配置 `fixed: 'left' \| 'right'` 且提供明确 `width`；`TableColumn<T>` 的 `key` 需为 `keyof T` 或内置伪列（`'selection' \| 'action' \| 'operation' \| 'index' \| 'expand'`） |
| **表单新增/修改字段与校验** | `*-edit.tsx`（Zod `schema` + `fields`）→ `src/api/<m>.ts` | 字段 `name` 必须与 Zod schema 和后端 DTO 字段一致；编辑回填通过 `initialData` 传入 `CustomForm` |
| **修改筛选/分页参数** | `src/api/<m>.ts` → `*-index.tsx` → `src/mock/modules/...` | 筛选条件变化时必须重置 `currentPage = 1` 并清空 `selectedIds` |
| **变更接口路径或响应结构** | `src/config/api-url.ts` → `src/api/<m>.ts` → `src/mock/...` | 路径统一只在 `API_URLS` 修改，严禁在页面或 Mock 中硬编码 URL 字符串 |
| **新增全屏/无侧边栏页面** | `src/components/layout/conditional-layout.tsx` | 将路径前缀加入 `NO_LAYOUT_PATHS` 即可跳过 `Layout` 壳 |
| **新增页面级 SEO** | `src/app/<route>/layout.tsx` | Client Component 页面无法直接 `export const metadata`，需在同目录建 Server Component `layout.tsx` 导出 `metadata` |
| **扩展或修改基础 UI 组件** | `src/components/ui/*` / `src/components/custom/*` | 业务通用能力优先沉淀到 `custom/`，保持 `ui/` 贴近 Shadcn/ui 原始语义 |

## 6. 核心自定义组件开发要点

### 6.1 `CustomTable`（`src/components/custom/table/custom-table.tsx`）

- **固定列机制**：采用 `border-separate border-spacing-0` + `position: sticky`，在 `useMemo` 内单次 $O(C)$ 预计算左右偏移量与边界标记，横向滚动阴影通过 `passive` 监听 + `rAF` 切换 DOM `data-scroll-left` / `data-scroll-right` 属性实现，**滚动过程零 React 重渲染**。
- **暗色背景对齐**：主内容卡片在暗色模式使用 `dark:bg-white/[0.03]` 叠加在 `dark:bg-background` 上，固定列与表体统一使用不透明的 `color-mix(in srgb, white 3%, hsl(var(--background)))` 及其悬停合成色，禁止改回半透明 `bg-muted/50`（会导致横向滚动文字穿透）。
- **类型约定**：`TableColumn<T>` 必须保持单一接口类型（不可改为分发联合类型），否则会导致 `render(_, record)` 的 `record` 退化为隐式 `any`。
- **列宽规范**：使用 `fixed: 'left' | 'right'` 的列必须显式设置数值型 `width`，以便准确累加多列固定偏移量。

### 6.2 `CustomForm`（`src/components/custom/form/`）

- 内部封装 `react-hook-form` + `zodResolver`，字段配置通过 `fieldMap`（`Map`）做 $O(1)$ 查找。
- `Field` 已做 `React.memo` 优化；联动字段可使用 `watchFields` + `onChange` 回调，避免无条件开启 `watchAll`。
- 数据转换工具 `formatFormData` / `formatSubmitData` 位于 `src/components/custom/form/utils.ts`。

### 6.3 通用弹窗与上传组件

- `CustomDialog` / `ConfirmDialog`：均已 `React.memo` 化；`CustomDialog` 默认屏蔽遮罩点击与 ESC 关闭，防表单误关丢失数据。
- `FileUpload`：支持单文件与多文件拖拽排序（`@dnd-kit`），子组件 `UploadBox` / `SortableItem` / `FilePreview` 均在模块顶层 `memo` 化，扩展时切勿在组件函数体内定义子组件或在 `setState` updater 内调用外部 `onChange`。

## 7. 开发规范与避坑清单（Human & AI 通用）

1. **包管理器**：项目锁定 `yarn@4.7.0`（`packageManager` 字段），执行安装/脚本统一使用 `yarn`，不要混用 `npm install` 生成 `package-lock.json`。
2. **禁止在组件内部定义子组件**：会导致每次渲染重建组件类型并反复卸载/重挂载 DOM（丢失焦点、重置输入状态）。
3. **禁止用内联字面量作为默认对象 prop**：如 `value = {}` 会在每次渲染产生新引用，触发依赖它的 `useEffect` 死循环或误重置状态，应提取模块级常量（如 `const EMPTY_VALUE = {}`）。
4. **定时器与异步请求必须防泄漏与防竞态**：所有防抖 `setTimeout` 需在 `useEffect` 清理函数内 `clearTimeout`；远程搜索需使用递增请求 ID（`requestIdRef`）丢弃过期响应。
5. **状态枚举统一**：启禁用状态全项目统一为 `0 = 启用`、`1 = 禁用`，一律引用 `src/config/forbidden-flag.ts`，不要硬编码魔法数字。
6. **换行符与格式**：项目已通过 `.editorconfig` 与 `.gitattributes` 统一文本文件为 `LF` + `UTF-8` + 2 空格缩进。
7. **变更验收**：每次修改代码（尤其是新增 `layout.tsx` / `page.tsx` 路由文件）后，务必执行：
   ```bash
   npx next typegen && npx tsc --noEmit
   ```
