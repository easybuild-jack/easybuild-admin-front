# EasyBuild Admin — 新一代中后台管理系统前端脚手架

> 一款清爽、美观、开箱即用的现代化中后台前端框架，为全栈工程师、前端及后端工程师量身打造。

---

## 一、项目定位

**EasyBuild Admin**（中文名：**易构**） 是一套业务无关的企业级中后台前端脚手架。它提供的不是某一个具体的业务系统，而是一套 **可复用、可扩展、可快速交付** 的通用中后台解决方案。

无论是零售电商、仓储物流、内容运营、企业 OA，还是任何需要后台管理的业务场景，都可以基于此脚手架快速搭建，实现从 0 到 1 的高效落地。

**脚手架的三大核心价值：**

- **业务无关** — 所有菜单、页面、权限均由后端动态下发，前端不硬编码任何业务逻辑。更换一套后端接口，它就是另一个全新的管理平台。
- **按需组装** — 脚手架内置了多种通用业务模块（权限管理、基础数据、内容运营、系统配置等），均可根据实际业务自由选择、裁剪或扩展。后端决定"有哪些模块"，前端自动生成对应菜单与导航。
- **即插即用** — 新增一个业务模块，只需创建页面文件 + 后端注册菜单资源，前端侧边栏自动出现新菜单，无需修改任何路由配置文件。

## 三、核心亮点 — 动态菜单与业务模块的灵活组装

### 3.1 后端驱动的动态菜单系统

这是本脚手架 **最核心的设计理念** —— **前端不决定"有什么菜单"，后端说了算。**

**工作机制：**

1. 用户登录成功后，前端自动向后端请求菜单资源接口
2. 后端根据当前用户的角色和权限，返回该用户可见的菜单资源树（包含菜单名称、路径、排序、层级关系等）
3. 前端自动将后端返回的菜单数据转换为路由配置，动态渲染侧边栏导航
4. 菜单数据智能缓存 30 分钟，避免重复请求，页面切换零延迟

**这意味着什么？**

- **不同角色看到不同菜单** — 管理员看到全部模块，运营人员只看到运营相关模块，财务只看到财务报表，完全由后端权限控制，前端零干预
- **业务模块自由组合** — 每个模块都是独立的，后端不返回该菜单资源，前端就不会出现该入口。上线一个新模块或下线一个旧模块，只需修改后端配置
- **新增模块无需改路由** — 前端创建页面文件，后端注册对应菜单资源，侧边栏自动出现新菜单项，图标与颜色通过映射表自动匹配
- **跨行业通用** — 同一套脚手架代码，A 项目做零售管理，B 项目做仓储管理，C 项目做内部 OA，只需后端配置不同的菜单资源树即可

## 五、与后端对接规范设计

### 5.1 统一的接口通信协议

所有 API 请求遵循统一的 **请求-响应-异常** 三层处理机制：

**请求层**：Axios 拦截器自动注入 Token 请求头，后端无需关心前端如何传递认证信息。

**响应层**：后端接口统一返回标准结构：

```json
{
  "code": "OK",          // 状态码：OK / UN_LOGIN / UN_AUTH / ERROR
  "data": { ... },       // 业务数据
  "msg": "操作成功",      // 提示信息
  "count": 100           // 分页总数（列表接口）
}
```

**异常层**：前端自动识别并处理以下场景 —
- `UN_LOGIN` → 自动清除登录态，跳转登录页
- 业务错误 → 统一 Toast 提示错误信息
- 网络超时 → 友好的网络异常提示
- 服务不可用 → 兜底异常展示

### 5.2 标准化的 API 路由设计

所有业务模块的接口遵循 **统一命名规范**：

| 操作 | 接口路径模式 | 说明 |
|------|------------|------|
| 分页查询 | `/{domain}/{module}/queryPage` | 支持搜索条件 + 分页参数 |
| 新增/编辑 | `/{domain}/{module}/addOrEdit` | 有 ID 则编辑，无 ID 则新增 |
| 启用/禁用 | `/{domain}/{module}/disable` | 统一的状态切换接口 |
| 删除 | `/{domain}/{module}/delete` | 单条/批量删除 |
| 下拉列表 | `/{domain}/{module}/selectList` | 用于关联选择的精简数据 |

后端只需按此规范实现接口，前端即可快速接入。**一个新的 CRUD 模块最快 30 分钟内完成前后端联调。**

### 5.3 认证与权限对接

| 环节 | 机制 |
|------|------|
| **登录认证** | 前端加密密码 → 后端返回 JWT Token → 前端自动解析并持久化 |
| **请求鉴权** | 每次请求自动携带 Token 头，后端校验即可 |
| **菜单权限** | 后端通过菜单资源接口下发当前用户可见菜单，前端动态渲染 |
| **角色授权** | 后端提供资源树 + 角色资源关联接口，前端提供树形勾选授权界面 |

### 5.4 本地 Mock 调试机制

项目内置基于 Next.js App Router 的轻量级 Mock 引擎，无需启动真实后端即可本地完整调试：

- **单入口路由转发**：`src/app/api/[...slug]/route.ts` 统一接收 `/api/*` 请求并交由 `src/mock/index.ts` 分发（生产环境自动返回 404）。
- **模块化管理**：Mock 数据与接口按业务域存放在 `src/mock/modules/`（`auth`、`base`、`operation`、`customer`、`system`、`common`），路由 key 直接复用 `API_URLS` 常量，并通过 `globalThis` 持久化内存状态。
- **开箱体验模块**：开发环境（`.env.development`）默认启用 **权限管理（部门/角色/员工）、基础设置（分类/品牌/分组/标签）、运营管理（Banner）、会员管理（用户）、系统设置（字典与字典项）** 及通用文件上传 Mock；未做 Mock 的业务模块在 Mock 菜单中自动隐藏，连接真实后端（如 `.env.test` 中的 `http://localhost:5001/api`）即可按后端菜单权限完整展示。

## 八、快速上手

```bash
# 启用 Corepack（自动激活项目指定的 Yarn 4.7.0）
corepack enable

# 安装依赖
yarn install

# 启动开发环境（默认端口 4000，内置本地 Mock 接口）
yarn dev

# 构建生产版本
yarn build:prod

# 启动生产服务
yarn start:prod
```

- **访问地址**：`http://localhost:4000`
- **默认 Mock 登录账号**：账号 `admin` / 密码 `12345`
- **环境切换**：开发环境（`.env.development`）默认对接内置 Mock（`/api`）；测试环境（`.env.test`）指向本地后端 `http://localhost:5001/api`
- **环境要求**：Node.js ≥ 20.9，Yarn 4.7.0（Corepack 管理）
